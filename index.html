Project 01 · House Of Ong R

서비스 간 데이터 정합성 확보

Overview — 개요

인증 기능과 사용자 기능을 분리하는 과정에서 발생한 회원가입 실패 및 데이터 불일치 문제를 해결했습니다. 서비스 간 요청이 부분적으로 실패하더라도 데이터 정합성을 유지하고, 재시도와 복구가 가능한 구조를 만드는 것이 목표였습니다.

Problem — 문제 상황

기존에는 인증과 사용자 기능이 하나의 서비스에서 처리됐지만, 기능을 분리한 이후 회원가입 과정에서 문제가 발생했습니다.

웹 3/9

Project 01 · House Of Ong R

문제 시나리오

  1. 사용자가 회원가입을 요청합니다.
  2. 사용자 서비스에서 사용자 데이터가 저장됩니다.
  3. 인증 정보 생성 과정에서 오류가 발생합니다.
  4. 사용자 데이터는 남아 있지만 인증 정보는 생성되지 않습니다.
  5. 사용자가 재시도하면 기존 데이터와 충돌해 정상적으로 가입할 수 없습니다.

서비스별 데이터 저장이 독립적으로 수행되면서, 하나의 회원가입 요청이 부분적으로만 완료될 수 있었습니다.

Reason — 원인 분석

  • 재시도에 대한 안전성 부족: 동일한 요청이 반복됐을 때 중복 데이터나 충돌이 발생할 수 있었습니다.
  • 부분 실패에 대한 처리 부족: 한 서비스의 실패가 다른 서비스에 이미 반영된 데이터를 자동으로 되돌리지 못했습니다.
  • 데이터 복구 절차 부족: 요청 처리 도중 발생한 불일치를 찾아 복구하여, 결과적 정합성을 달성하는 절차가 필요했습니다.

Project 01 · House Of Ong R

Solve — 해결 방안

회원가입 과정에서 각 서비스의 처리 결과를 구분하고, 중간 단계에서 실패하더라도 데이터가 불일치한 상태로 방치되지 않도록 처리 흐름을 개선했습니다.

Implementation — 핵심 구현

① 멱등성 확보

  • 요청의 중복 여부를 확인할 기준을 정의합니다.
  • 이미 처리된 요청을 구분해 중복 실행을 방지합니다.
  • 네트워크 오류나 응답 유실로 인한 재시도에도 안전하게 처리되도록 합니다.

② 실패 시 보상 처리

  • 각 단계의 성공 및 실패 상태를 구분합니다.
  • 후속 단계가 실패하면 이전 단계의 결과를 보상하는 절차를 수행합니다.
  • 보상 처리 자체가 실패할 가능성도 고려해 별도 복구가 가능하도록 합니다.

③ 데이터 정합성 점검 및 복구

  • 인증 정보와 사용자 데이터의 불일치 여부를 확인합니다.
  • 복구가 필요한 데이터를 식별합니다.
  • 재처리 또는 보상 처리를 통해 정상 상태로 복구합니다.

Project 01 · House Of Ong R

Effect — 개선 효과

  • 중복 요청 대응: 재시도로 인해 발생할 수 있는 중복 처리 문제를 방지합니다.
  • 실패 복구 가능성: 중간 단계 실패 시 데이터 상태를 복구할 수 있는 절차를 마련했습니다.
  • 운영 안정성: 요청 처리 중 해결되지 않은 데이터 불일치를 확인하고 복구할 수 있도록 개선했습니다.

Review — 회고

서비스 간 데이터 정합성은 정상적인 요청 흐름만으로 보장되지 않습니다. 중간 실패와 재시도, 복구 과정까지 함께 설계해야 합니다. 이번 경험을 통해 기능을 서비스별로 분리하는 것뿐 아니라, 서비스 경계를 넘어 데이터의 상태를 어떻게 유지하고 복구할 것인지 고려하는 것이 중요하다는 점을 확인했습니다.

향후에는 장애 상황별 테스트를 확대하고, 불일치 발생과 복구 이력을 추적할 수 있도록 관측 가능성을 강화해 데이터 정합성을 더욱 안정적으로 관리하고자 합니다.
